# Velora 产品级生产交付实施方案

状态：执行中  
实施分支：`main`  
目标环境：`ubuntu@175.27.250.53`  
原则：保持现有门户与管理后台顶栏、分组菜单、配色和 ProComponents 组件体系；不修改 Casdoor 源码，不启用 Velora 自建 OIDC Provider。

## 一、交付判定

只有同时满足以下条件才可结束本轮：

1. `make verify`、生产配置检查和真实浏览器 E2E 全部通过。
2. 运行制品能准确追溯到 Git 提交、构建时间、镜像摘要和配置摘要。
3. 管理员能够在 Velora 完成日常用户、组织、角色、应用、审批、审计和安全管理，无需进入 Casdoor。
4. 登录、空权限、应用授权、账号下发、停用恢复、退出和回滚均有自动化及生产证据。
5. 所有变更以小步 Conventional Commits 提交并及时推送 `main`，每个阶段均可独立回滚。

外部 HA、异地灾备、WORM/SIEM、真实国密 KMS/HSM、渗透与合规认证必须使用真实目标环境形成证据。缺少资源时只交付适配、门禁、运行手册和证据模板，不得伪造认证结论。

## 二、实施阶段

### Phase 0：基线与视觉保护

- 保存当前生产容器、镜像、配置和数据库备份信息。
- 固化后台壳、顶栏、菜单、主题 Token 和关键页面视觉基线。
- 建立问题—代码—测试—生产证据追踪表。

验收：回滚点明确；任何后续提交不得改变既有导航身份和门户视觉语言。

### Phase 1：清除生产门禁

- 对 ProComponents 与 Ant Design 依赖做按需分包，修复首屏、最大分包和总包预算。
- 逐条处理 gosec 发现：真实缺陷修复；误报以最小范围注释并记录安全依据。
- 保持 `govulncheck` 可达漏洞为零，执行 staticcheck 和 golangci-lint。
- 为 Server、Worker、Web、Edge 注入准确的 revision/version/build time/source 标签；发布只使用不可变制品摘要。
- 修复 `make verify`，确保完整门禁可重复运行。

验收：`make verify` 全绿；生产健康接口不再报告 `dev`；运行 Web revision 与页面资源提交一致。

### Phase 2：真实浏览器 E2E

- 建立仓库内 Playwright 工程，国内镜像安装浏览器。
- 覆盖登录、MFA、Turnstile 风险触发、退出、无权限空态、菜单权限和错误恢复。
- 覆盖应用七个页签、部门/组/角色/人员授权、排除优先、审批与执行、账号下发、停用恢复。
- 覆盖主要桌面与窄屏视口、分页位置、卡片重叠、页签和后台壳视觉回归。
- `ci-web-e2e` 纳入 `verify` 与 Jenkins，失败即阻断发布。

验收：E2E 在干净环境和生产验收账号上均可执行，截图、trace 和报告可追溯。

### Phase 3：后台核心产品闭环

- 工作台增加账号下发失败、异常登录、锁定用户、待执行变更、即将过期权限/密钥和系统健康。
- 审批中心统一显示待审批、已批准待执行、执行失败；提供业务深链和明确下一步。
- 用户详情补齐解锁、审批重置密码、MFA 状态、会话处置、账号来源和生命周期影响预览。
- 平台设置补齐组织信息和结构化安全设置；普通管理员不直接填写底层 namespace、dataId、存储地址和摘要。
- 操作记录接入完整性校验、审批导出、归档/WORM/SIEM 状态。

验收：管理员的日常操作全部在 Velora 完成；每个敏感写操作具备权限、审批、审计、错误恢复和状态反馈。

### Phase 4：规模化治理与接入

- 权限检查支持按应用、角色、部门、用户范围发起，提供批量处理、完成率、逾期和提醒状态。
- 应用接入明确开发/测试/生产环境，管理各环境回调、Client、账号下发目标、检查和密钥轮换。
- 上线检查提供可定位的失败原因、修复建议和重试；保留安全的短期一次性凭据交付。
- 完成所有页面、按钮、列名、空态、错误态和危险操作文案走查，删除无效说明和 AI 味文案。
- 加入键盘、焦点、缩放、对比度、读屏名称和响应式自动检查。

验收：新应用按标准流程完成接入，不需要修改 Velora 代码、不需要进入 Casdoor、不依赖口头指导。

### Phase 5：生产发布与交付

- 先备份数据库与运行配置，再部署不可变制品。
- 执行健康、依赖、登录、权限、审批、账号下发、审计、备份和回滚验收。
- 输出提交、镜像摘要、配置摘要、测试结果、生产证据和回滚命令。
- 外部能力进入风险台账，明确责任人、前置资源和验收标准。

验收：生产全部服务健康，关键流程真实通过，回滚制品可用，代码与证据已推送。

## 三、提交与回滚策略

- 每个 Phase 至少一个独立提交；较大 Phase 按门禁、API、UI、E2E、部署继续拆分。
- 每次提交前执行受影响测试；每个 Phase 结束执行完整门禁并立即 push。
- 数据库仅使用向前兼容迁移；普通代码回滚不删除新增表或历史审计数据。
- 生产发布前保留旧镜像 ID、不可变回滚标签、Compose 和环境文件备份。

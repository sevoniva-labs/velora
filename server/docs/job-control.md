# 作业治理核心

`internal/platform/jobcontrol` 是作业中心的后端规则核心，不依赖 Kratos、数据库、消息产品或前端。它统一约束：

- 状态流转：运行、成功、失败、重试、死信、补偿、回滚、取消。
- 重试上限和指数退避，达到上限自动进入 `DEAD_LETTER`。
- 每次作业必须有业务幂等键，定义和运行记录不允许跨任务复用。
- 启动作业、人工补偿、回滚、取消等高风险动作必须携带审批号。
- 状态变更必须先形成审计事件；审计写入失败时返回错误，调用方应在同一持久化事务中回滚状态变更。

该包是 `Built-in` 规则核心；数据库存储、可靠消息、告警、控制台、备份恢复和发布回滚属于 `Adapter slot`，不能由页面绕过状态机直接改状态。生产启用前仍需接入平台审批、审计和告警实现，并完成目标环境演练。

# 配置变更治理

`internal/platform/configchange` 是配置中心的 `Built-in` 变更规则核心。它不把 Nacos 的发布接口当作审批系统，要求每次变更具备版本、期望前版本、内容 SHA-256、不可变引用和组织归属。

- 配置变更默认进入 `PENDING_APPROVAL`，创建人不能审批自己的变更。
- 只有批准人可以发布该版本；发布和回滚均产生审计事件。
- 回滚先进入 `ROLLBACK_PENDING`，再由独立操作人执行；审计失败时 fail-closed。
- 敏感值只允许保存摘要和受控引用，禁止把明文密码、Token、私钥写入历史表或审计详情。

Nacos 3 是配置 `Profile`，配置版本持久化、审批、审计、发布、回滚、告警和控制台属于 `Adapter slot`。真实生产仍需接入组织审批、密钥/配置保险箱和目标 Nacos 集群演练，当前不宣称监管或目标厂商认证。

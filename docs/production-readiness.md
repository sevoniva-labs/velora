# Velora 生产就绪状态

## 结论

当前版本达到受控单机企业生产交付基线，可继续接入业务应用；不等于金融机构最终生产认证。最终 Go/No-Go 仍需完成目标环境的高可用、灾备、国密设备、安全运营和外部测评。

## 已完成

- Portal、隐藏身份协议域、Reference App 和 Spectra 已完成生产部署与健康检查。
- 用户资料已支持真实姓名、性别、手机、邮箱、头像、验证状态、乐观并发、审计及 Casdoor 同步；管理端与个人中心均可编辑。
- 显示名称、邮箱等应用必要属性变更后，会递增账号下发版本并向已授权应用重发兼容事件；敏感资料不默认下发。
- 微信网站扫码登录、绑定、解绑、MFA step-up、一次性 state/票据、未绑定拒绝和隐藏 Casdoor 链路已实现并部署，正式入口保持关闭直至取得微信开放平台网站应用凭据。
- 微信扫码、回调、绑定和会话完成均有低基数结果/耗时指标及对应 Prometheus 告警规则。
- 管理后台覆盖组织、人员、角色、应用、使用范围、账号下发、审批、审计、配置和安全管理。
- 应用接入支持多环境回调、自动创建 OIDC Client、一次性接入交付、应用角色、四类授权范围、全链路检查、发布和停用。
- 新增每应用独立目录接口，支持组织、部门和本应用已授权用户的全量及增量读取。
- 前后端测试、真实 Playwright E2E、安全扫描、供应链证据、配置检查和回滚流程已纳入 `make verify`/Jenkins。
- 文档已收敛为单一接入手册、架构、运维、安全和生产状态，不再保留冲突历史方案。

## 发布门禁

必须同时满足：

1. `make verify` 全绿。
2. `make check-prod-config` 全绿。
3. 生产健康和依赖就绪均为 `UP`。
4. 真实账号登录、无权限、应用启动、账号下发、目录读取、停用和退出通过。
5. 当前提交、运行版本、镜像摘要、数据库备份和回滚标签可追溯。
6. 生产 Secret 不在 Git、日志、镜像和验收报告中出现。

## 维护方式

每次生产发布只更新本文件的“当前生产版本”和未完成外部事项，不再新增按日期命名的交付报告。发布命令与回滚流程见[《生产运维》](./operations.md)。

生产运行版本以服务器 `/opt/velora/prod/runtime/DEPLOYED_COMMIT` 为唯一依据，发布目录中的镜像摘要、备份标识和回滚记录共同构成验收证据，不在文档中维护容易失真的固定提交号。每次发布必须复验 `/api/v1/system/health`、`/ready`、真实账号登录、个人资料、应用列表、微信关闭态和 Spectra 健康检查。
